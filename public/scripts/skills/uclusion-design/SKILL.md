# Uclusion Design

Follow the selected capsule assignment. The author owns the contract, publication and reconciliation. A cold reviewer returns findings to the author. The coordinator carries bounded requests and results; each role interprets its own evidence and authority.

Read linked procedures completely when their actions below apply. Reuse current held bodies; reload changed, incomplete or lost instructions. A missing required procedure stops affected work: return its exact path and update/restart requirement.

Return completed scope, remaining work or exact blocker, and confirmed or unfinished receipts to the coordinator.

## Capsule author

Fetch the selected target and relevant incoming records with `get_job`, using `initial_read:true` for the first whole-target read. The returned Job header establishes job membership; return a standalone thread to its responsible role with the evidence. Read every advertised standing-note R-thread completely with `thread_only:true`, retaining actual versions. Fetch incoming codes exactly and qualify nested local codes with their question identity.

Establish the actual job, capsule owner, complete current body, advertised R-code and actual version. A cohesive job uses its own capsule; an independent top-level task uses its own without job fallback; grouped work uses its top-level parent's. Verification-produced work retains its originating contract and a named delta. Comments supply context. An explicit capsule/version pin must match; available version hints alone are not pins, and reads return current state. Reconcile missing, conflicting or forwarded changed evidence before the next affected decision, preserving newer confirmed state.

Use the original request, verbatim human instructions and supplied identities to locate evidence. For job question/suggestion evidence and actions, use [job-assistance](../uclusion/references/job-assistance.md) for qualification and role ownership: clear non-AI, non-advisory answers or Approvable For votes qualify; Human Resolve delegates choice and leaves versioned handling pending. The question owner completes required replies/votes. Retain the question/option text, selected outcome, exact identities, handled rendered version, pending state and intended targets; validate them before publication. Return no-change settlement to the question owner. A newer qualifying answer that conflicts with the current body requires the changed contract to be established before affected work resumes, even if no repository edit was needed.

Before permitted Uclusion writes, use [durable-records](../uclusion/references/durable-records.md) for threading, authorship and receipts. File material missing facts, unsettled choices or permissions before affected composition using `ask_question` under [question-tools](../uclusion/references/question-tools.md). Unknown observations need an open question; real discrete choices may have options. Source inspection does not establish unobserved runtime behavior. Preserve independent human permissions and approved type, quantity and scope for any investigation or verification performed. Return needed work outside this role to the caller with the target, requested outcome and available evidence/receipt identities.

Check relevant settled decisions before relying on a supplied design or asking a possibly settled question. Reuse loaded evidence or a successful export while current, complete and sufficient. When more history is needed, use [history-search](../uclusion/references/history-search.md) to obtain the configured export and request a bounded search through the coordinator: exact successful path, question/mode and applicable constraints. Use returned findings and support; distinguish a completed no-match result from an incomplete search. Request bounded investigation when relevant source evidence is missing.

Write a concise, standalone contract for the next actor. Open with `## Summary` to orient them to files or surfaces and the shape of the change. Put material outcomes, implementation constraints and approval limits below it. Include a test plan when implementation requires testing, preserving actual approval. Support material claims with nearby links. For an accepted option, use the returned canonical parent-question URL and identify the question, full qualified option code/name and accepted behavior.

Before publication, request a fresh independent cold reviewer through the coordinator, with the target, candidate location and evidence needed for its claims. Reconcile findings against the evidence. Correct straightforward errors; present material unresolved disagreement to the human with the decision and consequences. Cold-review findings inform the contract without supplying human authority.

When saving new context, use `add_info` on the current capsule R-thread, or ordinary target notes while the capsule is absent. Use [capsule publication and incorporation](../uclusion/references/capsule-dispatch.md) when creating or replacing a capsule, acknowledging incorporation, or reconciling a current-capsule update. Return its confirmed identities and unfinished outcomes so the requesting role can establish the prerequisite for its affected work.

## Bounded cold reviewer

Assess the supplied candidate for the assigned target using the relevant evidence. Fetch scoped current records, including governing standing notes when relevant, to establish ownership, contract identity or a material claim. Return supported findings, their effect on the candidate, and any exact evidence or decision still missing. Keep the review within its assigned scope; the author reconciles findings and owns publication.
