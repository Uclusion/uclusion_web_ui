# Backlog maintenance

## Batch run

find_work backlog_maintenance starts one batch: backlog_maintenance_run with action:claim and exact since/through; refusal skips it. Present/select work without waiting, following session-handoff.md. Export with --completed and every completed code; retain exact successful path/full stdout. That stdout alone supplies dependency matches and incomplete lines, never rescan. Fresh export-search.md maintenance helper gets those inputs through history-search.md and scans outcome impact for the whole batch.

## Record the run

First exact code in each numbered finding is recipient, not Evidence source/blocker codes. Export/scan incompleteness means report gaps and do not record; claim expiry returns notice.

Otherwise print findings, then silent add_info of complete findings/reasons/evidence/proposals on each candidate lacking equivalent saved outcome findings in the synced export. Export's current capsule/note/reply sections choose current R-code; absent capsules get ordinary job/task notes, independent tasks never job fallback, grouped tasks parent capsule, bugs direct replies. No MCP dedup read, ledger or deterministic identifier; no exactly-once promise.

Inspect each write; failure/uncertainty prevents run record. Reconcile against synced export, retry only absent findings. Once every contextual write/equivalent succeeds, backlog_maintenance_run with action:record, same claim_id and aggregate Markdown report: one linked human inbox report, silent writes suppress extra human notifications but preserve normal UI pushes and existing Poke routing including author. No maintenance marker/guaranteed recipient agents. With no findings, print no-candidate result and record without report/inbox item.

These contextual writes are the only candidate-mutation exception: never change contract/body/stage, suggest or resolve candidates. Later human actions reload exact target and apply normal authority/workflow.
