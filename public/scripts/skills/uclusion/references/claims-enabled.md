# Enabled work claims

## Automatic selection

Human selection subscribes directly.

For native Codex, automatic selection must first have a confirmed native claim, then a confirmed subscription identifying the same canonical work and agent. A denied or uncertain claim creates no subscription and starts no substantive work. If registration fails after a grant, retain that exact claim and report unfinished adoption; retry registration with the same identity, or release the claim if adoption is abandoned. Reconcile an uncertain grant or lost lease before automatic work begins. The root performs these identity-bound mutations. Claude Code and Cursor keep their existing claim step for automatic selection, then subscribe. An unavailable claim operation leaves automatic adoption unfinished.

When the continuing native assignment requires a claim after a bug moves into a job, first confirm the canonical job's claim and matching subscription. Denial or uncertainty leaves the handoff unfinished. Preserve the former bug's grant identity for separate claim cleanup; release its original canonical claim key rather than re-resolving the moved code.

## Retention and release

For native Codex, retain each grant's agent and canonical work identity. Claim ownership and subscriptions use the same verified root identity; connection IDs only track the transport. Release the granted canonical short code from that root. A helper or another root sharing its connection cannot release the grant. Reconnect results recover or lose each exact pair; do not assume a missing or legacy receipt confirms native ownership. Never silently downgrade to connection-only claiming.

The coordinator decides held-claim retention or release from the assignment's actual handoff and responsible-role outcomes. At a real blocked, review or complete assignment handoff, release the identified held claim through the exposed release operation using its actual schema, except that review/package waits retain the claim through the terminal execution outcome and confirmed record. Report an unavailable, denied, failed or uncertain release as that outcome. Preserve the held-claim identity and actual retention/release outcome separately from assignment disposition.
