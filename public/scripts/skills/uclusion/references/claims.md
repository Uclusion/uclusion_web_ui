# Work claims

## Retention and release

The coordinator decides held-claim retention or release from the assignment's actual handoff and responsible-role outcomes. At a real blocked, review or complete assignment handoff, release the identified held claim through the exposed release operation using its actual schema, except that review/package waits retain the claim through the terminal execution outcome and confirmed record. Report an unavailable, denied, failed or uncertain release as that outcome. Preserve the held-claim identity and actual retention/release outcome separately from assignment disposition.

Implementation combines its own substantive completion confirmation or the standalone producer's current confirmation with handled package selection, completed or declined selected actions and confirmed terminal recording to report release eligibility for a finished Reviewable job or resolved bug. Missing or changed substantive completion facts require reassessment; action and terminal-receipt gaps leave execution unfinished.

Apply the responsible role's qualified continue, wait or release eligibility result to the matching retained assignment, separately from the claim receipt. A claim release alone supplies no assignment-release result. A partial package leaves the unfinished enclosing job retained. Pending work or package outcomes keep the assignment retained even when a claim has been released or a release attempt recorded. An ordinary answer, task resolution, intermediate handoff or audit receipt alone does not release the assignment.
