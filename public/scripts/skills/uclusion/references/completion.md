# Review/standalone preparation and operation role packages

## What the package says

Use lane-prepared package thread, reviewed changes and exact notification scope. End job review with package after provenance; a bug fixed here gets its own add_info package on resolved bug. No ask_question/assistance. Explain exactly what all does, in order:

1. Commit only reviewed changes, naming repositories/files or compact scope/count.
2. Push only those commits.
3. Clear only exact completed job, otherwise exact review plus resolved tasks; bugs exact bug/replies. Clear last, one call/code, terminal record on last so no later attempt write notifies.

For ask_for_review, pass the narrative in report and the package in completion_package; the tool appends the package last.

No repository changes means omit commit/push. End: "Reply `all`, or tell me in your own words what you want."

## Publication and presentation

Return the same confirmed durable package/text and exact thread for immediate root presentation before follow-on work; never wait for turn end. The preparing role decides whether a qualifying reply already suppresses the invitation; the operation role handles its selection. A bug-package response is its reply. If qualifying reply already arrived, suppress invitations and handle it; no repeated full package at later turn ends.

## The reply

The operation helper qualifies and interprets replies; only non-AI/non-advisory human thread/chat replies qualify. all grants exactly listed actions; other wording is ordinary instruction, ambiguity one narrow clarification where received. Decline-all completes without action; later replies are new instructions, never repeat finished work. Package grants no tests/builds/provider calls/deploy/security/force-push/unrelated changes/broader clear/candidate mutation/context clear.

Until reply, retain assignment; later turns end with one thread-naming line only, no discovery/other work. Claims remain independently gated. Poked reply is read before action; chat needs no read.

## Carrying it out

Run authorized actions in order, stop at first failure without rollback. Nothing to commit/push/clear is successful no-op. Fixed authorized scope clears directly, no notification preview; report actual outcome.

One terminal record per attempt, replying to the exact human thread reply or package root thread for chat. State reply/completed/failed/remaining. If clear authorized and prior steps succeeded, pass record to last clear_notifications even when empty; otherwise add_info, silently if clear authorized. Reconcile uncertain record in exact package thread before writing only if absent. Same-reply retry performs only unfinished work and writes one new record. Lane assignment release still requires its distinct conditions.
