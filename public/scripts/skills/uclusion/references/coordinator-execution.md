# Coordinator implementation checks and task resolution

## Independent permission decisions

Dispatch only in Doable/Reviewable with helper-validated current contract. An explicit job test plan approves tests; an explicit human-authored job security plan approves security. Otherwise ask each unresolved test type/quantity or proposed security choice and await job-assistance.md's qualifying answer.

Security includes authentication/authorization, secrets/credentials, threat/trust boundaries, sensitive persistence/lifecycle and shared infrastructure. Reviewer security labels are evidence, never approval for expansion.

## Before dispatching or resuming edits

Handle Pokes; resolve answered questions and resulting capsule changes; resolve completed/duplicate/inapplicable tasks. Confirm target/owner/current R-code/version, executable effective stage, qualifying human evidence and every permission. Keep evidence/tracking, stop affected edits on changed prerequisites and refresh the brief before resumption.

## Bounded implementation dispatch

Use helper-dispatch.md fresh implementation for each independent task; grouped work keeps parent's helper, cohesive jobs keep job contract. Design help never substitutes. Pass exact scoped grant/selected role, not copied/reconstructed contract. Reconcile Review direction yourself. Retain ownership/Pokes/questions/task selection/resolution/approvals/review/package; code review is separately fresh.

## Task resolution and remaining Review work

Implement active/grouped tasks, never redo resolved work. Resolve when written and tested; commit/push/deploy never hold that closure. Record remaining commits/pushes/deployment/agreed other-environment verification as Review work, not automatically new tasks or Doable. Implementation failures use ordinary new/reopened-work gates. Durably record returned decisions/tradeoffs/followups/unreconstructable findings once; review/completion own handoff.
