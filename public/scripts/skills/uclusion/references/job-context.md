# Job entry and current contract

## Scoped job context

Retain initial whole-scope initial_read decision evidence. Subsequent reads fetch only changed sections; include description when needed/uncertain, and after restoration if its complete body is missing. Description-change Pokes require it; summaries never substitute.

## Select the target and current contract

Before implementation dispatch/resumption identify selected target, expected capsule owner and advertised current R-code/actual version. Executable stage supplies none of these. One cohesive job pass uses its job capsule; unrelated independent top-level tasks use separate complete own capsules/helpers, never job inheritance/fallback. Grouped work keeps its top-level parent's capsule/helper. Verification-produced work remains in its originating pass without a new capsule, reported as a named scope-expansion delta even when tracked as a task.

Dispatch exact target/owner/reference/version through helper-dispatch.md without fetching/reconstructing the body solely for dispatch. The helper reads and validates returned job/owner/current reference/note/version before edits. Your substantive decisions need complete governing bodies/evidence; held capsules match all those identities or require current R-thread read. Comments are context only and refresh on whole-scope/exact-thread refresh even if body version matches. Superseded/historical capsules never substitute. Default whole-job reads omit token audits; explicit thread/notes reads retrieve them.

Publisher canonical receipts satisfy reference dispatch, not a coordinator body copy. Missing capsule selects capsule-dispatch.md without execution preloading/permission. Historical completed work may finish review without backfill; resumed/changed implementation needs current contract. Requires Input locks only implementation; independent investigation/reproduction/measurement may continue. Blocked and Requires Input remain distinct despite Debatable UI; Doable/Reviewable do not prove assistance handled.

## Assigned-job updates

Assigned current-capsule Updated: stop affected edits, read its current R-thread and Reports; human edits also use capsule-dispatch.md cleanup/reconciliation before refreshed identities/requirements/permissions resume helpers. Generic updates read only needed sections, description when uncertain.

Added readiness arrives after its transaction: one reload contains item and new stage, never await another stage Poke. A stage-named event records that stored transition without confirmation get_job/stage_only; it proves no unchanged content/assistance/effective-stage prerequisite or assignment. Doable resumes only this assignment after all gates. A conversion records held unchanged body/type or reads only that thread if missing; it reports no stage and may change it without a stage event, so retain effective-stage checks. Reviewable promises neither finality nor unrun deployment/environment verification.

## Plan mode and handoffs

Plan mode limits repository/machine changes, not Uclusion artifacts. File known questions/suggestions immediately; before plan exit durably save missing plan information in its proper artifact and show link. Chat/local-only plans are unfinished.
