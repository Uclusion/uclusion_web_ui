# Helper target and current contract

## Current scoped evidence

Working roles retain their own complete initial whole-scope `initial_read:true` evidence. Actual returned Job header chooses the lane. Subsequent reads fetch changed/needed sections; include description when needed/uncertain, on description-change Pokes and after body loss/restoration. Exact threads keep their scope. Current comments are context, not contract; refresh them on whole-scope/exact-thread updates even if body version matches. Standing notes and other resolved discussions require explicit complete reads. Superseded/historical bodies never replace the current contract.

## Determine ownership yourself

Before affected action identify selected target, expected capsule owner, advertised current R-code and actual version from current evidence. A cohesive job uses its own capsule; unrelated independent top-level tasks require separate complete own capsules/fresh helpers, never job inheritance/fallback. Grouped work uses its top-level parent's capsule/helper. Verification-produced work stays in its originating pass without a new capsule, reported as a named scope-expansion delta even when tracked as a task.

Read the governing body and validate returned job, owning target, advertised current reference, note identity and actual version. A version match alone proves no selected identity. Root-provided references and publisher receipts are locators/confirmed produced states, not body substitutes. Missing/mismatched/changed evidence stops affected actions for this role's reconciliation or a capsule handoff; never paste a newer version into a stale authorization.

No capsule selects the fresh sibling design role, without execution preloading. Historical completed work can finish review without backfill; resumed/changed implementation needs current contract. Requires Input locks implementation, not independent permitted investigation. Blocked and Requires Input remain distinct despite Debatable UI. Doable/Reviewable supply neither current contract nor handled assistance/permissions.

## Updates and authority

Current-capsule Updated stops affected edits: read current R-thread and Reports. Human edits require capsule role's obsolete-review cleanup/reconciliation before affected work resumes with current identities/requirements/permissions. Generic updates read only needed sections, description when uncertain. Root forwards identities/messages; the working role handles prerequisites itself.

Added readiness arrives after its transaction: one reload contains item and new stage; never wait for another stage Poke. A named stage event records its stored transition without confirmation lookup, but proves no other prerequisite or assignment. Doable resumes only the retained assignment after current gates. Conversion retains known unchanged body/type or reads that exact missing thread; it reports no stage and may change it without a stage event, so preserve effective-stage checks. Reviewable promises neither finality nor unrun environment verification.

For actual job actions, order current evidence, questions, suggestions, applicable approval, executable-stage work and review. The question role owns assistance and explicit human-authorized transitions; review owns final implementation publication's conditional Doable-to-Reviewable exception. No other resolution/value approval/capsule grants transition. Use stage_only after an operation when effective stage is needed, preserving newer events.

Plan mode limits repository/machine changes, not Uclusion artifacts. File known questions/suggestions immediately with permitted lane tools; before plan exit durably save missing plan information in its proper artifact and return its link. Chat/local-only plans are unfinished.
