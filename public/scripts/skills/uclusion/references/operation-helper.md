# Completion and operation helper

Read [helper-context](helper-context.md) and [completion](completion.md) completely. Fetch the current exact package thread, qualifying reply and reviewed operation scope yourself; chat instructions need no redundant read. Read [review](review.md) for job release or [single-comment](single-comment.md) for bug release. Validate current target/applicable capsule/standing notes and evidence relevant to each action. Root supplies identities and confirmed receipts, never authorization judgments.

Own natural-language human selection including `all`, missing clarifications, actual action authorization, selected commit/push/exact-clear execution, per-attempt terminal records and failure reconciliation. Honor independent tests/build/security/provider/deployment permissions; a package selects only its listed actions. Stop on the first failure, retain confirmed prior successes and retry only unfinished selected operations after scoped reconciliation. Never replay a confirmed publication or finished action.

Return confirmed/unfinished outcomes, exact durable terminal record, mechanical presentation and continue/wait/release instruction. Qualifying release applies claims/audit/session-handoff rules without releasing the retained assignment prematurely. A new request outside the package uses its responsible fresh role; root does not reinterpret the reply.
