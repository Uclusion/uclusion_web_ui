# Working role handoffs and notifications

ask_for_review returns no notifications. Read get_notifications only for a human inbox request or a decision needing contents, never merely review/package/signoff/commit/resolve or preview of fixed exact clear scope. The package is the item's sole clear offer. Outside it, ask before exact-work clearing; if a necessary read finds none, make no clear call. Once exact scope is authorized, clear directly and report actual outcome.

## Context-clear boundary

Always offer the client's normal fresh-chat command, once per eligible boundary, only after a resolved standalone view bug/question with unrelated/unknown next work, or fully signed-off job with applicable commit made and nothing queued. Once per boundary; never mid-job/related work/review/wait. Preserve the offer because later turns replay finished context.

## Helper progress, remaining work and handoffs

Auto-taken turns leave substantive new results/decisions/blockers/next steps durable; add only information not already recorded, never unchanged state/reloads/turn boundaries. Ordinary checkpoints/turns are not handoffs. A real human-block/review/completion/pause/interruption handoff applies assignment-aware discovery, claims/audit, exact durable blocker, bug package/job review-release, notification/context/commit rules.

The responsible role judges remaining independent authorized work; root mechanically starts the returned role or waits for real updates/human input. Ordinary checkpoints do not justify stopping authorized work. Timeout is no shutdown deadline.

Continue all authorized independent work after artifacts/links; questions block only dependents. Before ending a retained Doable turn, reconcile remaining tasks, review and agreed calibration work against current evidence under the normal refresh gates. Resolve tasks already written and tested under implementation-helper.md; continue unfinished authorized work and use review.md when implementation is ready. Settled questions or empty assistance alone never establish completion.

End for a real completion/review handoff, explicit human pause or when no authorized action can proceed. If blocked, state the exact blocker and needed human action, if any. Continuation never overrides stage, permission or provider stop rules; do not invent work or spin on failed actions to keep a turn open. Open packages use completion.md's presentation/reply/later-turn line; otherwise return the exact pending decision/completed task presentation and apply the one-time hint/discovery/context-clear triggers. At the first retained human-guided wait/completed package, load [work-discovery](work-discovery.md) for its once/session informational hint without fetching work. The handing-off role owns eligibility, claims/audit and remaining-work judgments; root follows its confirmed continue/wait/release instruction without loading this policy. Turn endings never trigger discovery or another list.
